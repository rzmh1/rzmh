# تقرير جرد رُزمة قبل إعادة التصميم

**تاريخ الفحص:** 2026-11-21  
**المستودع:** `rzmh1/rzmh`  
**فرع العمل:** `codex/ruzmah-full-redesign`  
**النطاق:** فحص ساكن لملفات المصدر والوثائق ومسارات التطبيق. لا اتصال بقاعدة الإنتاج أو Northflank أو مزودي الدفع والذكاء الاصطناعي.

## 1. خلاصة تنفيذية

رُزمة ليست مشروعًا فارغًا ولا تحتاج إلى إعادة كتابة من الصفر. التطبيق الحالي منصة قائمة تعمل ببنية Node.js 24 وواجهات JavaScript ES Modules دون إطار عمل واجهات ثقيل، وقاعدة SQLite، وتخزين ملفات محلي أو S3-compatible، مع رحلة تعلم واختبارات وجدولة واشتراكات ومدرس ذكي ولوحة مالك.

الفرع الحالي يحتوي خطة إعادة التصميم في `docs/CODEX_REDESIGN_PLAN_AR.md`. مقارنة الفرع مع `main` أظهرت 11 commit إضافيًا، وكان الملف المختلف الظاهر في نتيجة المقارنة هو ملف الخطة؛ لم يظهر تنفيذ إعادة تصميم للواجهات أو الوظائف الجديدة في ملفات التطبيق. لذلك يبدأ العمل من المنتج الحالي مع الحفاظ عليه، لا من افتراض أن مراحل الخطة قد نُفذت.

**القرار الهندسي:** تطوير تدريجي متوافق مع البيانات الحالية، مع فصل المعاينة التجريبية عن التطبيق وبيانات الإنتاج، وعدم استبدال SQLite أو تغيير مخططها إلا بترحيل إضافي مختبر.

**تحديث حالة التنفيذ:** هذا التقرير هو خط أساس قبل تنفيذ التعديلات، وليس وصفًا حرفيًا للحالة الحالية. أضيفت لاحقًا ميزة المرفقات، والتحقق من البريد، وقسم التسريبات، وصندوق «اسأل رُزمة» الخاص، ومكتبة دائمة لمصادر المدرّس الذكي. راجع `docs/REDESIGN_IMPLEMENTATION.md` و`docs/AI-TUTOR-IMAGES.md` للحالة الأحدث.

| الجزء | الموجود فعليًا |

| الذكاء الاصطناعي | OpenAI Responses API من الخادم، مع حفظ المحادثات وقياس الاستخدام وحد يومي |
| الإدارة | لوحة مالك ذات 20 تبويبًا تقريبًا تشمل الطلاب والمحتوى والاختبارات والملفات والدفع وAI والنسخ والتدقيق والتخصيص |
| الاختبارات | اختبارات Node، واختبارات Playwright، وسير CI لبناء Node 24 وChromium وDocker |

## 3. ما يعمل حاليًا

### تجربة الزائر والمتجر
- صفحة تسويقية للزائر، وصفحات المسارات والدورات والمدرسين والتحديثات.
- معاينة محتوى محدد، وتسجيل حساب مجاني، وصفحة أسعار، ومراجعة طلب منفصلة.
- لا تعرض صفحة النجاح اشتراكًا مؤكدًا من تلقاء نفسها؛ تتحقق من حالة الطلب المحفوظة على الخادم.

### مساحة الطالب
- تسجيل الدخول، اختيار المسار والدورات والمدرسين، وتهيئة أولية متعددة الخطوات.
- خطة تعلم ومهام يومية وأسبوعية، وإعداد وقت المذاكرة، وتسجيل تقدم الدروس وأجزاء الفيديو.
- بنك أسئلة، تدريب فردي، اختبارات مؤقتة، نتائج ومراجعة ودفتر أخطاء.
- ورقة مسودة للرسم، وحساب الطالب واشتراكه.
- حفظ التقدم والمحاولات والخطة على الخادم وربطها بحساب الطالب.

### لوحة المالك
- إدارة الأقسام والمسارات والمدرسين والدورات والدروس والأسئلة والاختبارات والتحديثات.
- إدارة رفع الوسائط، والطلاب والاشتراكات، وإعدادات Stripe وAI، وسجل الأحداث والنسخ الاحتياطية.
- تخصيص متقدم يحفظ نسخ HTML/CSS/JavaScript ويعرضها داخل iframe معزول بقيود CSP.

## 5. ملاحظات أمنية وبيانات

### ضوابط موجودة في المصدر
- كلمات المرور تُشتق باستخدام scrypt مع salt، والجلسات تحفظ بصمة token لا قيمة token الخام.
- Cookie الجلسة HttpOnly وSameSite=Lax، وتُضاف Secure في الإنتاج.
- توجد حماية CSRF للطلبات المغيّرة، والتحقق من Origin في الإنتاج، وحدود طلبات لبعض المسارات.
- صلاحية الإدارة تُفحص على مسارات `/api/admin/`، وبيانات محاولات الاختبار والمحادثات مرتبطة بمعرف المستخدم.
- أسرار الإعدادات تُشفّر باستخدام AES-256-GCM، ومفتاح APP_KEY يبقى في بيئة الخادم.
- تفعيل اشتراك Stripe يعتمد على Webhook وتوقيعه وتطابق المبلغ والعملة ووضع Test/Live، مع منع تكرار الحدث.
- الملفات الخاصة تمر عبر فحص الصلاحية، والفيديوهات تُعالج وتُحفظ مع حالة معالجة.
- إطار التخصيص يستخدم iframe sandbox وCSP تمنع الاتصال الشبكي من الإطار.

### مخاطر/نقاط تحتاج تدقيقًا واختبارًا
1. إضافة البريد والتحقق منه واستعادة كلمة المرور تتطلب مزود بريد موثوقًا، وآلية رموز أحادية الاستخدام ومحددة العمر، وحدود إرسال، ورسائل لا تكشف وجود الحساب.
2. قبل السماح بصور الطلاب، يجب وضع حد للحجم والنوع، والتحقق من الملف الفعلي، ومعالجة مؤقتة، وعدم حفظ الصور في مكتبة عامة، وتحديد مدة الاحتفاظ.
3. يجب قصر سياق المدرّس على مواد رُزمة المنشورة والمصرح بها التي يستطيع الطالب الوصول إليها، مع مرجع داخلي حقيقي، وعدم ادعاء استرجاع مصدر غير موجود.
4. يجب عدم نشر إفادات الاختبارات كحقائق رسمية أو قبول صور/نصوص أسئلة سرية أو محمية. النشر يمر بمراجعة بشرية وإزالة البيانات الشخصية.
5. يجب أن تحفظ الطلبات شروط الباقة وقت الشراء حتى لا تتغير حقوق الاشتراك القديم عند تعديل الأسعار أو المزايا.
6. أي منشئ صفحات أو كود مخصص يحتاج مسودات ومعاينة معزولة وسجل إصدارات وتراجع، ولا يجوز أن يصل إلى جلسات الطلاب أو مفاتيح API.
7. لا توجد بيانات اعتماد أو بيئة staging متاحة ضمن فحص المستودع؛ لا يمكن إثبات اتصال Stripe/OpenAI/S3 أو إعداد Northflank الفعلي من قراءة الكود.

## 6. حماية البيانات والترحيل

- جداول الحسابات والجلسات والاشتراكات والطلبات والنتائج والمحادثات والتقدم موجودة في SQLite الحالية.
- توجد ترحيلات إضافية سابقة مع نسخ احتياطية قبل ترحيل منصة التعلم.
- لن يُستخدم `reset` أو `seed` على قاعدة بيانات حقيقية، ولن تُستبدل قاعدة الإنتاج بقاعدة جديدة.
- أي تغيير في الجداول سيُنفذ بترحيل إضافي، مع نسخة اختبارية منزوعة البيانات الشخصية واختبار rollback/restore.
- لا يتطلب نموذج المعاينة أي اتصال بقاعدة البيانات أو API أو مفاتيح خارجية، ويستخدم بيانات اصطناعية فقط.

## 7. خط الأساس للاختبارات

يسجل تقرير التشغيل المرفق في المستودع بتاريخ 2026-11-19 النتائج التالية: `npm run build` ناجح، و`npm run check` بنتيجة 29/29، واختبارات Chromium بنتيجة 5/5، وبناء وتشغيل Docker على Node 24. كما يذكر أن Stripe وOpenAI اختُبرا باستجابات محاكية، وأن S3 خضع لاختبار توقيع محلي، ولم يتم نشر Northflank أو اختبار بيانات الإنتاج.

**تنبيه دقة:** هذه نتائج موثقة في التقرير السابق للمشروع وليست إعادة تشغيل مني في جلسة الفحص الحالية. لم أتمكن عبر موصل GitHub وحده من تنفيذ `npm ci` أو `npm run build` أو الاختبارات محليًا. ستُعاد الاختبارات في CI بعد رفع تغييرات الفرع إلى Pull Request.

## 8. ترتيب التنفيذ المقترح

1. إنهاء المعاينة التفاعلية المعزولة لكل الصفحات الأساسية، بحالات الجوال والكمبيوتر وبيانات تجريبية.
2. اعتماد اتجاه التصميم، ثم تنفيذ نظام التصميم والمكونات المشتركة.
3. تطوير رحلة الطالب والتنقل وقسم التسريبات مع نموذج مراجعة المالك.
4. تطوير المدرّس الذكي ومكتبة المعرفة والسبورة المتدرجة، مع منع الإجابات غير المدعومة.
5. تطوير إدارة الموقع والباقات والكوبونات والصفحات والسياسات.
6. إكمال التحقق من البريد واستعادة كلمة المرور بعد إعداد مزود بريد.
7. تنفيذ اختبارات الانحدار والأمان والواجهة والترحيل، ثم مراجعة تقرير النتائج.
8. تجهيز Pull Request بوضع Draft للمراجعة فقط؛ لا دمج أو نشر تلقائيًا.

## 9. حدود هذا الفحص

هذا تقرير فحص ساكن للمصدر والوثائق، وليس شهادة أمنية أو اختبار اختراق. لم تُقرأ قاعدة إنتاج، ولم تُستدع خدمات مدفوعة، ولم تُعرض بيانات مستخدمين. كما لم تُجر معاينة متصفح جديدة أو اختبار أجهزة فعلية في هذه الجلسة. أي فجوة لم يثبتها المصدر صيغت كشيء يحتاج تحققًا، لا كعطل مؤكد.
