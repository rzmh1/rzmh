# ترقية رُزمة إلى 3.0

## قبل التحديث

هذه ترقية إضافية للمصدر الحالي، وليست استبدالًا لقاعدة بيانات المنصة. لم تكن قاعدة إنتاج أو مفاتيح تشغيل متاحة في مساحة العمل؛ اختُبر الترحيل على قاعدة قديمة مصطنعة للاختبار، ولم يُنفَّذ على حسابات حقيقية.

1. احتفظ بنسخة من المصدر القائم وملف `.env` في مكان خاص.
2. نفّذ `npm run backup` على الاستضافة الحالية، وانسخ النسخة إلى وجهة آمنة منفصلة.
3. انسخ مجلد الوسائط إن كان التخزين محليًا، أو فعّل نسخ/Versioning للحاوية السحابية.
4. احتفظ بـ `APP_KEY` نفسه. تغييره يجعل الأسرار المشفرة السابقة غير قابلة للقراءة.
5. جرّب الترقية أولًا على نسخة معزولة من البيانات، مع تعطيل التكاملات المالية والمدفوعة في بيئة التجربة.

## تحديث المصدر

أوقف خدمة التطبيق وقت استبدال الملفات. ارفع المصدر الجديد مع الإبقاء على `.env` ومجلد `DATA_DIR` وملفات الوسائط الموجودة. لا تحذف Docker volume، ولا تشغّل `docker compose down -v`.

```bash
npm ci --omit=dev
npm start
```

أو أعد بناء حاوية Docker مع volume البيانات نفسه. يجب توفر FFprobe وFFmpeg؛ عند التشغيل المباشر يمكن تحديد `FFPROBE_PATH` و`FFMPEG_PATH`.

## ما يحدث عند أول تشغيل

- إذا كانت قاعدة SQLite موجودة ولم يُطبَّق ترحيل التعلم، تؤخذ نسخة متسقة باستخدام `VACUUM INTO` في `DATA_DIR/backups/before-learning-*.sqlite` قبل الترحيل.
- فشل إنشاء النسخة يمنع الاستمرار في الترحيل.
- تُضاف جداول المدرسين والملفات التعليمية والاختيارات والخطط والمهام والتقدم وجلسات المذاكرة، وحقول مدة الفيديو وأبعاده.
- تُضاف مسارات الكمي واللفظي ومواد التحصيلي وSTEP إلى المحتوى الذي لم يكن يتضمن مسارات تعلم. يمكن إدارتها وتغييرها بعد ذلك.
- يُحفظ محتوى الدورات والدروس والأسئلة والأقسام السابق، وتُضاف له حقول تنظيمية افتراضية فقط. لا تُزرع أسماء مدرسين أو نتائج طلاب.
- يُسجل الترحيل داخل `app_migrations`. لا تتكرر الإضافة أو النسخة السابقة عند التشغيل التالي.
- تبقى جداول الحسابات والجلسات والاشتراكات والمدفوعات والوسائط وAI والتخصيص وبياناتها. تُحترم علامات إكمال الدروس القديمة ذات المعرف الفريد عند بناء التقدم الجديد.

نسخة SQLite لا تضم الفيديوهات ولا `APP_KEY`؛ لهما نسخ منفصلة. سياسات الاحتفاظ الدورية قد تحذف النسخ القديمة، لذلك انقل نسخة ما قبل الترحيل إلى وجهة آمنة.

## فحص ما بعد التحديث

افتح `/api/health`، ثم سجل دخولًا بحساب المالك القائم. لا تُعد إنشاءه لمجرد التحديث. راجع الدورات، وأضف مصدرًا واربطه بدورة اختبار، وقِس مدة فيديو قديم من المكتبة. أنشئ طالب قبول جديدًا وجرّب الرحلة والاختيارات والجدول، وتأكد أن الطالب لا يصل إلى API الإدارة.

افحص حسابًا قائمًا واشتراكه ومدفوعاته وتقدمه. جرّب الصفحة والدرس والخطة على iPhone وكمبيوتر في الوضعين. اختبارات الحزمة لا تغني عن اختبار البيانات والخدمات الفعلية على الاستضافة.

## العودة عند الحاجة

أوقف التطبيق واحتفظ بنسخة من الوضع الذي تريد التراجع عنه أولًا. أعد المصدر السابق ونسخة قاعدة ما قبل الترحيل مع `APP_KEY` الأصلي والوسائط. تعامل مع WAL/SHM أثناء توقف الخدمة فقط وفق دليل النشر. الرجوع لنسخة قاعدة قديمة لا يضم أي تقدم أو دفعات أُضيفت بعدها؛ اختبر آلية الاستعادة في بيئة معزولة قبل تطبيقها على الإنتاج.

## تحديث المتجر من 3.0 إلى 3.1

لا يحتاج هذا التحديث جداول جديدة. إعدادات المتجر و`previewLessonId` حقول اختيارية في وثيقة المحتوى القائمة؛ لا تُستبدل الحسابات أو الاشتراكات أو التقدم. خذ نسخة قاعدة ووسائط أولًا واحتفظ بالبيئة والمفتاح. يُستخدم أول درس مجاني قديم كمعاينة عند غياب اختيار صريح؛ المعاينة تتطلب حسابًا. اختيار «بدون معاينة» يعطلها دون حذف الدروس. الدورات المجانية بالكامل تبقى مجانية بعد الدخول. راجع `STOREFRONT-FINAL.md` وخطوات اختبار القبول قبل النشر.
