# تقرير فحص وإصلاح التشغيل

التاريخ: 2026-11-19. المستودع: `rzmh1/rzmh`. المرجع الذي بدأ منه العمل: `afdc36e168485eb0b6ce7c5dcff12346206ceb95` على `main`. فرع الإصلاح: `fix/production-readiness-node24`؛ لا دمج أو نشر تلقائي.

## النطاق والبنية

حُصرت الملفات الأصلية الـ85 قبل إعادة التنظيم، مع فحص الوحدات والاستيرادات والموارد وأوامر التشغيل والاختبارات والترحيل والتوثيق. [الجرد الكامل](FILE-INVENTORY.md) يربط كل ملف أصلي بمساره الحالي ويبيّن ما تغيّر محتواه. لم يحذف ملف أصلي، بما في ذلك التقارير القديمة والمعاينة وملفات التوافق والملفات التي لا تستدعيها الواجهة حاليًا.

كانت جميع الملفات في الجذر رغم اعتماد package.json والخادم والاختبارات على مجلدات غير موجودة. أُعيدت البنية المقصودة من الشفرة نفسها:

- `server/`: HTTP والحسابات وSQLite والصلاحيات والتعلم والترحيل والجدولة والتخزين والدفع وAI والتخصيص.
- `dist/`: وحدات الواجهة الأصلية وHTML وCSS؛ الخطوط والشعار والمحرر المجمع في `dist/assets/`. بقيت ملفات التصميم والواجهة الأصلية دون تغيير.
- `client/`: مصدر CodeMirror ومعاينة التصميم.
- `scripts/`: البناء والتحقق والإعداد وإدارة المالك والنسخ والتصدير وخادم التوافق.
- `tests/`: الاختبارات الأصلية واختبارات التشغيل الجديدة؛ `tests/browser/` لفحوص المتصفح.
- `docs/`: الأدلة والتقارير السابقة والمعاينة المحفوظة، مع تقرير الإصلاح ودليل Northflank والجرد.

لا يُحذف `dist` أثناء البناء؛ هذه ملفات الواجهة الأصلية التي تُطوَّر مباشرةً في هذا المشروع. ليس المشروع تطبيق Vite/React ولا أُعيدت كتابته.

## ما أُصلح

1. مسارات تشغيل الخادم والسكربتات والاختبارات واستيرادات server↔dist وclient↔dist، ومسارات CSS والخطوط والشعار والمحرر أصبحت تطابق الملفات الفعلية.
2. أصبح `npm run build` يبني `client/editor.mjs` إلى `dist/assets/editor.bundle.js` بمسارات مستقلة عن cwd، ثم يتحقق من شجرة استيرادات التطبيق ومن CSS. بقيت وحدات الواجهة وتصميمها ووظائفها كما كانت.
3. سابقًا كان `npm run check` يعيد نجاحًا مع **صفر اختبارات** لغياب مجلد tests. صار runner يجمع قائمة صريحة، يرفض القائمة الفارغة، يفحص صياغة JavaScript في جميع مجلدات المصدر، ويمرر فشل أي اختبار إلى exit code. أضيف `npm test` و`npm run test:browser`.
4. حُدّث توقع اختبار قديم كان يمنع مجرد ذكر أدوات الطالب في وصف الاشتراك؛ صار يتحقق من عدم وجود روابط مباشرة لأدوات الطالب في المتجر، بما يتوافق مع التصميم الحالي واختبارات المتجر الأحدث. لم تُحذف الأدوات أو نصوص التصميم لإرضاء الاختبار.
5. Docker متعدد المراحل على Node 24: تثبيت اعتماديات البناء حتى مع NODE_ENV إنتاجي، بناء المحرر، إزالة اعتماديات التطوير من التشغيل، نسخ ملفات التشغيل فقط في طبقة واحدة، مستخدم غير root، مجلد بيانات قابل للكتابة، FFmpeg/FFprobe، واحترام PORT وفحص صحة.
6. أُضيف `.dockerignore` و`.gitignore` لمنع إدخال الأسرار وقواعد SQLite وruntime والاعتماديات ونتائج الاختبارات في المصدر والصورة، و`.env.example` بأسماء الإعدادات دون قيم سرية. لم تُضف مفاتيح أو كلمات مرور تشغيل إلى الكود.
7. إعدادات خاطئة مثل PORT غير صالح وسائق تخزين غير مدعوم وفترات نسخ غير صالحة تفشل مبكرًا، بدل تشغيل غير متوقع أو مؤقت نسخ سريع جدًا. بقيت المسارات والافتراضات الصحيحة السابقة كما هي.
8. تُرفض أجسام JSON غير الكائنية والمسارات المشفرة غير الصالحة أو المحتوية على NUL برد 400 بدل خطأ خادم 500.
9. معالجة SIGTERM/SIGINT لتصريف HTTP والتحويل الجاري قبل إغلاق SQLite، بحد إنهاء 25 ثانية. ملف خادم التوافق يستدعي مسار التشغيل نفسه.
10. أُصلح تصدير المعاينة القديم ليضم كل ملفات CSS والثيم والخطوط محليًا بدل ترك روابط موارد مفقودة، مع الحفاظ على أداة التصدير والمعاينة السابقة.
11. أُضيفت CI على Node 24 للبناء والاختبارات وChromium وبناء Docker، ودليل تشغيل Northflank دون تعديل خدمة إنتاج أو قاعدة بيانات.

## التحقق الفعلي

| الفحص | النتيجة والنطاق |
| --- | --- |
| `npm ci` | نجح بالاعتماديات المثبتة في lockfile |
| `npm run build` | نجح، مع CodeMirror وفحص شجرة الاستيرادات وCSS؛ أهداف Safari 16 وChrome 110 |
| `npm run check` | **29/29** ناجحة، دون فشل أو تخطٍّ أو اختبارات ملغاة |
| `npm run test:browser` | **5/5** ناجحة في Chromium الفعلي، دون اعتراض استجابات API أو محاكاتها في المتصفح |
| واجهة RTL | 13 صفحة عامة بعرضي 1440 و390 بكسل، دون أخطاء JavaScript أو موارد HTTP مفقودة أو تمرير أفقي؛ الخط المحلي، الثيم واستمراره، قائمة الجوال ولوحة المفاتيح |
| الحسابات والإدارة | تسجيل ودخول وخروج واستمرار الجلسة؛ منع الطالب من الإدارة؛ جميع تبويبات الإدارة العشرين والمحرر المحلي وحفظ إعدادات المتجر ثم إعادة تحميلها |
| الطالب والجدولة | خطوات الترحيب الثماني واختيار دورات حقيقية وحفظ خطة وإعادة حسابها بعد تغيير الوقت واستمرارها؛ اختبارات مدد ومعاينات وصلاحيات وتقدم وتقييمات |
| الاشتراكات | أسعار الخادم، قفل الحساب غير المشترك، التمديد والانتهاء وفصل Test/Live والتوقيع والمبلغ ومنع تكرار التفعيل؛ Stripe في اختبارات الخادم محاكى |
| التخزين والفيديو | رفع محلي وتحويل H264/MP4 وقياس FFprobe فعلي، حماية الفيديو وRange؛ توقيع S3 محلي دون اتصال بحاوية |
| الترحيل | قاعدة اختبار قديمة: نسخة قبل الترحيل وبقاء الحسابات والاشتراكات والمحتوى والإعدادات؛ لا قاعدة إنتاج مستخدمة |
| ملفات التشغيل | HTTP لكل الملفات المنشورة مع MIME صحيح؛ منع نشر `.env` وruntime وserver وpackage.json؛ إعداد يحافظ على مفتاح قائم وإيقاف CLI عبر SIGTERM |
| Docker | نجح البناء وتشغيل production بمستخدم UID 1000، Node 24.22.3 وFFmpeg/FFprobe 5.1.9؛ PORT=8080؛ صحة وموارد وتسجيل وSecure cookie ونسخة SQLite؛ بقاء الحساب والنسخة بعد restart، وإنهاء SIGTERM بكود 0 |
| `npm audit --omit=dev` | صفر ثغرات معلنة لاعتماديات الإنتاج وقت الفحص |
| تصدير المراجعة | نجح `node scripts/export-design-review.mjs /tmp/rzmh-review.html` |

نُفّذت اختبارات المصدر على Node 24.22.1. سُلّمت اختبارات المتصفح في المستودع؛ لإعادتها: `npm ci` ثم `npx playwright install chromium` ثم `npm run test:browser`. يمكن استخدام Chromium مثبت عبر `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

احتاج بناء Docker داخل بيئة المهمة إلى شهادة وكيل HTTPS الخاصة بالبيئة، مُرّرت كـ BuildKit secret من Dockerfile مؤقت خارج المستودع مع إبقاء TLS مفعّلًا. لم تُضف الشهادة إلى المشروع أو الصورة. استُخدم VFS محدود المساحة في البيئة؛ بعد حذف طبقات COPY المؤقتة الخاصة بهذه المهمة وتقليل نسخ ملفات التشغيل إلى طبقة واحدة اكتمل البناء. لا تغييرات على daemon أو بيانات خارج الاختبار.

## ما بقي قبل اعتماد الإنتاج

- لم تتوفر بيانات اعتماد Northflank أو قاعدة الإنتاج أو ملفات الوسائط الفعلية؛ لم تُغيَّر إعدادات استضافة أو قرص أو قاعدة قائمة، ولم يُنفذ نشر. التوافق المحلي لصورة Docker لا يثبت إعداد TLS/ingress/volume في الحساب الفعلي.
- يلزم اختبار اتصال S3/R2 وStripe Checkout وWebhook وOpenAI بمفاتيح المالك. لا تعتبر المحاكاة أو توقيع رابط تخزين إثباتًا لنجاح مزود خارجي.
- يلزم فحص Safari/iOS وAndroid على أجهزة فعلية، واختبار فيديو وحمولات كبيرة وحدود CPU/ذاكرة ومساحة القرص على بيئة staging. أهداف esbuild وعرض الجوال في Chromium ليست اختبار Safari.
- تبقى حدود التصميم الحالية: نسخة Node واحدة وSQLite بقرص دائم، وتحويل فيديو متسلسل داخل الخادم. التحويل الذي يتجاوز مهلة الإيقاف قد ينقطع ويحتاج إعادة رفع؛ لم يُضف طابور خارجي أو يُغيّر نوع قاعدة البيانات.
- راجع [Northflank](NORTHFLANK.md) و[الترقية الآمنة](UPGRADE-3.md)، واحتفظ بـAPP_KEY وDATA_DIR والقرص والوسائط القائمة. لا تغيّرها لأجل مطابقة أمثلة التوثيق.

تقارير المراحل القديمة محفوظة كسجل تاريخي؛ هذا التقرير هو مرجع التحقق الحالي.
