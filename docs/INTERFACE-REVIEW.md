# مراجعة واجهة رُزمة — تحديث التصميم

## ما تغير

التطوير داخل المشروع نفسه، باستخدام المكونات والمسارات والبيانات الحالية. لم تتغير ملفات `server/` أو نظام الدخول والدفع أو مخطط قاعدة البيانات، ولم تُشغّل قاعدة بيانات المنصة لإضافة بيانات تصميم. فحوص الخادم تعمل على قواعد مؤقتة منفصلة.

- افتتاحية تعليمية جديدة: عنوان ووصف من إعدادات الهوية، عرض بصري مخصص، ورابط لدرس مجاني موجود عندما يتوفر. النص يسبق الرسم على الجوال.
- بطاقات المسارات: شخصية مختلفة للقدرات والتحصيلي وSTEP، مع قراءة بيانات المسار من المصدر نفسه. المسارات القادمة لا تُقدّم على أنها منشورة.
- مركز جديد للتحديثات في `/#/updates`، مع تبويبات للتجميعات والتسريبات المتداولة، الاختبارات، الأكثر تكرارًا أسبوعيًا، والأسئلة الجديدة. التاريخ من بيانات النشر الفعلية فقط. الحالات الفارغة لا تُستبدل بأخبار أو أرقام مختلقة.
- ربط اختياري بين تحديث واختبار منشور: يظهر الرابط فقط عندما يوجد اختبار مرتبط ظاهر بالفعل. تبويب الاختبارات يشمل التحديثات المرتبطة باختبار حتى لو كان نوع التحديث «تجميعات».
- معاينة دورات تتغير بالاختيار، مع أول درس مجاني متاح ورابط الدورة. تبويباتها تدعم لوحة المفاتيح.
- المميزات بتكوينات مختلفة: المدرس الذكي، بنك الأسئلة، دفتر الأخطاء، الخطة، المسودة، التقدم، والاختبارات. الرسومات توضيحية دون نتائج أو نسب إنجاز مزعومة.
- اشتراك سنوي بارز، وثلاث مدد بديلة. الأسعار الأصلية لم تتغير، والسعر إجمالي للمدة، ولا يوجد تجديد تلقائي دون موافقة صريحة.
- تحسين بطاقات الدورات، القائمة العلوية والجوال، إغلاق القائمة بـ Escape، ورابط تجاوز المحتوى.
- الحفاظ على مصدر الشعار كما هو. يمكن للمالك إدخال نسخة ليلية اختيارية من الهوية نفسها. لا توجد إعادة رسم لشعار أصلي أو تغيير آلي لألوان صورته. الشعار النصي الموجود يبقى عند غياب ملف الشعار.
- ألوان الواجهة تتبع لون الهوية القابل للتعديل، مع درجات مشتقة للوضع الليلي. لا يوجد لون نعناعي.

## كيف أراجع النتيجة؟

يوجد ملف معاينة مستقل باسم `ruzmah-interface-review.html` مع التسليم. حمّله وافتحه بالمتصفح مباشرة. يُولد من **نفس مكونات الواجهة الفعلية**، مع الخطوط والتنسيق مدمجين، وليس مشروعًا بديلًا أو صورة للتصميم.

المعاينة تستخدم المحتوى الافتراضي المسمى توضيحيًا؛ لا تنسخ حسابات أو بيانات خاصة. يمكن التنقل بين الرئيسية والمسارات والدورات والدروس والتحديثات، وتجربة التصفية والتبديل بين الوضعين والمسودة. الدخول والشراء وحفظ التقدم يحتاج الخادم؛ تعرض المعاينة هذا بوضوح ولا تُنشئ حسابًا أو طلب دفع وهميًا.

لمعاينة النسخة التشغيلية بجميع الوظائف، استخدم المشروع:

```bash
npm ci
npm run setup
npm run setup:admin
npm start
```

ثم افتح `http://localhost:3000`. إذا كانت لديك `.env` وقاعدة بيانات قائمة، احتفظ بهما، ولا تُعد إنشاء حساب المالك لمجرد مراجعة التصميم. بعد تحديث ملفات واجهة في استضافة قائمة قد تحتاج تحديث المتصفح دون ذاكرة التخزين المؤقت.

يمكن إعادة توليد ملف المعاينة بعد التعديل:

```bash
node scripts/export-design-review.mjs /path/to/ruzmah-interface-review.html
```

## من الإدارة

- الهوية والرئيسية: العنوان والوصف والصورة والشعار الحالي ولون الهوية. حقل «نسخة الشعار للوضع الليلي» اختياري.
- التحديثات والتجميعات: اختيار النوع، كتابة المحتوى، واختيار اختبار مرتبط إن وجد. لا يحتاج إضافة حقول جدول أو ترحيل SQL؛ تستمر بنية المحتوى الحالية.
- الدورات والمسارات: تستمر إدارة الظهور والترتيب والصور والمحتوى كما كانت. الواجهة لا تعتمد على عدد ثابت من الدورات أو الأقسام.
- «الأكثر تكرارًا أسبوعيًا» يعرض الملخصات التي تنشرها الإدارة بهذا النوع؛ لا يخمّن إحصاءات تكرار لا توجد لها بيانات.

## التحقق

- اجتازت الاختبارات العشرة: الاختبارات التشغيلية السبعة السابقة، وثلاثة اختبارات جديدة للتصميم والتصفية ولوحة المفاتيح، والشعار والتباين والحسابات والحالات الفارغة.
- فُحص توليد 27 حالة صفحة، وتحليل CSS والتعامل مع محتوى مضاف ومخفي وفارغ، وصحة الروابط المرتبطة بالتحديثات.
- فُحص بدء ملف المعاينة دون طلبات API، وبوجود الخطوط والتنسيق داخل الملف.
- توجد قواعد للتجاوب تشمل 320/360/480/760/960/1100 بكسل وما فوق، وsafe areas، وأحجام لمس مناسبة، وتقليل الحركة. وجود القواعد وفحوص CSS لا يعادل قياس العرض في متصفح.
- **لم تتوفر أداة متصفح في الجلسة؛ لم تُجر معاينة بصرية فعلية على Safari iPhone أو الكمبيوتر في أي من الوضعين.** يلزم فتح المعاينة على الأجهزة المستهدفة وفحصها قبل الاعتماد النهائي. لم تُستخدم صور أو لقطات مزعومة لإيهام إتمام هذا الفحص.

## ملفات التغيير

- `dist/storefront.js`: تركيب الواجهة والتحديثات والمعاينات والأدوات والاشتراك.
- `dist/storefront.css`: تصميم الواجهة والتجاوب والوضعان.
- `dist/pages.js`, `dist/ui.js`, `dist/app.js`: الربط بمكونات المشروع ومساراته الحالية.
- `dist/admin.js`: حقلا ربط اختبار بالتحديث وشعار ليلي اختياري.
- `client/design-review.mjs`, `scripts/export-design-review.mjs`: إنتاج نسخة مراجعة من المكونات نفسها.
- `tests/storefront.test.mjs`: فحوص التحديث الجديد.

لم يُنشر التصميم تلقائيًا؛ هذه مرحلة المراجعة قبل اعتماد المالك. حزمة التشغيل تظل بحاجة إلى Node.js 24 أو Docker وقرص دائم، وفق دليل النشر الموجود.
