# سجل تنفيذ إعادة تطوير رُزمة

**الفرع:** `codex/ruzmah-community-finish-20261121`  
**آخر تحديث:** 2026-11-21

## ما أُنجز

### المرحلة 0 — الجرد
- فحص بنية المستودع والواجهة والخادم وقاعدة البيانات والاختبارات والوثائق.
- إنشاء `docs/REDESIGN_AUDIT.md` وتوثيق الموجود والفجوات وحدود الأمان.
- تثبيت أن المنتج الحالي يجب تطويره تدريجيًا، لا إعادة كتابته من الصفر.

### المرحلة 1 — المعاينة
- إنشاء `docs/ruzmah-redesign-preview.html` بمعاينة تفاعلية مستقلة وبيانات اصطناعية.
- توثيق الاتجاهات الثلاثة في `docs/DESIGN_PREVIEW.md`.
- اختيار الاتجاه التحريري الفاخر كأساس بصري أولي، مع إبقاء الاتجاه الأكاديمي والتقني للمقارنة.
- المعاينة لا تتصل بقاعدة البيانات أو مفاتيح الخدمات ولا تنفذ دفعًا أو تسجيلًا حقيقيًا.

### المرحلة 2 — نظام التصميم
- إضافة `dist/redesign.css` كطبقة CSS مستقلة تُحمّل بعد الأنماط الحالية.
- توحيد ألوان الخلفيات والأسطح والحدود والظلال والأزرار والبطاقات والصفحات الداخلية.
- تحسين غلاف الطالب ولوحة الإدارة والصفحات العامة مع دعم الجوال وتقليل الحركة.
- إبقاء ملفات CSS الأصلية والهوية القديمة موجودة لتسهيل التراجع.

### المرحلة 4 — البريد والتحقق من الحساب
- إضافة إرسال البريد عبر Resend من الخادم فقط، مع إبقاء مفتاح API في متغيرات البيئة.
- جعل التحقق من البريد مطلوبًا في الإنتاج افتراضيًا، برمز من 6 أرقام صالح 10 دقائق ومحدود المحاولات.
- إضافة استعادة كلمة المرور برمز مؤقت، مع إبطال الجلسات السابقة بعد تغيير كلمة المرور.
- إضافة دليل إعداد البريد في `docs/EMAIL-SETUP.md`. يتطلب التشغيل الفعلي توثيق نطاق المرسل وإضافة الأسرار في الاستضافة.

### المرحلة 5 — المدرّس الذكي والمرفقات والمكتبة الدائمة
- دعم صور JPG/PNG/WebP حتى 4 MB وملفات PDF حتى 5 MB.
- التحقق من نوع الملف وتوقيعه وحجمه على الخادم.
- إرسال المرفق إلى Responses API دون حفظ بايتاته في سجل محادثة رُزمة؛ يحفظ اسم المرفق فقط.
- إضافة توجيهات لاستخراج السؤال والخيارات وشرح الإجابة مع التصريح بالأجزاء غير الواضحة.
- توثيق حدود الميزة وتكلفة الصور والملفات في `docs/AI-TUTOR-IMAGES.md`.
- إضافة مكتبة دائمة لمصادر المدرّس الذكي من لوحة المالك، مع رفع متعدد للملفات أو فهرسة مستند سبق رفعه إلى مكتبة ملفات رُزمة.
- حفظ النسخة الأصلية في تخزين رُزمة، وفهرسة نسخة في OpenAI Vector Store، وربط المدرّس بأداة File Search في Responses API.
- دعم PDF وDOC/DOCX وPPTX وTXT وMD وHTML وJSON وأنواع محددة من ملفات البرمجة، بحد 512 MB و5 ملايين token لكل ملف وفق حدود OpenAI.
- عرض حالة الفهرسة وإعادة المحاولة وإزالة الملف من الفهرس دون حذف النسخة الأصلية، وإظهار أسماء المصادر في إجابة المدرّس عند توفر استشهادات.
- تقييد إدارة المكتبة للمالك فقط، ومنع حذف الملف الأصلي قبل إزالته من فهرس المدرّس.

### المرحلة 6 — رسائل المشتركين
- إضافة تبويب للمالك لمعاينة عدد المستلمين قبل إرسال أي رسالة.
- قصر المستلمين على الاشتراكات النشطة والحسابات ذات البريد المؤكد.
- فرض تأكيد أن الرسالة تشغيلية وليست تسويقية، ثم تأكيد إرسال ثانٍ.
- تقسيم الإرسال إلى دفعات لا تتجاوز 100 رسالة، مع مفاتيح idempotency وسجل للنتيجة.
- حد إرسال إداري واحد في الساعة؛ لا تُرسل أي رسالة فعلية قبل ضبط مزود البريد والضغط على تأكيد الإرسال من لوحة المالك.

### المرحلة 3 — قسم التسريبات (النسخة الأولى الآمنة)
- إضافة جداول مستقلة للإفادات والبلاغات، مع ترحيل إضافي لا يحذف أو يعيد إنشاء أي جدول قائم.
- إضافة API لإرسال الإفادة وقراءة المعتمد منها وإرسال بلاغ ومراجعة المالك.
- لا تظهر الإفادة للطلاب قبل اعتماد المالك عنوانًا ووصفًا عامًا منقحين.
- لا تُعرض هوية المرسل للطلاب، ولا تُعرض بيانات البلاغات الداخلية.
- إضافة القسم إلى تنقل الطالب السفلي والجانبي، وإضافة تبويب إدارة مستقل للمالك.
- إضافة اختبار انحدار يغطي منع الوصول قبل الاشتراك، وحجب الإفادات المعلقة، والتنقيح قبل النشر، ومنع تكرار البلاغ.

### المرحلة 7 — اسأل رُزمة (استفسارات خاصة وردود الإدارة)
- استبدال فكرة المنتدى المفتوح بصندوق استفسارات خاص؛ لا يرى الطالب إلا استفساراته وردود الإدارة عليه.
- وصول الاستفسارات إلى لوحة المالك فقط، مع تصنيفات قابلة للإضافة والتعديل والتفعيل والإيقاف.
- يكتب المالك الرد ويختار صراحةً إبقاءه خاصًا بصاحب الاستفسار أو نشر السؤال والرد معًا ليستفيد جميع الطلاب.
- لا يظهر السؤال في قائمة الإجابات العامة قبل وجود رد إداري وحفظ خيار النشر.
- يستطيع المالك رفض الاستفسار أو إغلاقه، مع حفظ السجل وعدم إظهاره للعامة.
- إضافة تبويب «اسأل رُزمة» للطالب وتبويب «استفسارات الطلاب» للمالك.
- استخدام جداول SQLite مستقلة؛ لا تغيير لبيانات الحسابات أو الاشتراكات أو النتائج الحالية.

## ما لم يُنفذ بعد

- لم يُنفذ استيراد Telegram أو تحويل الملفات تلقائيًا إلى أسئلة في بنك رُزمة. المكتبة الدائمة للمدرّس الذكي منفصلة عن بنك الأسئلة ولا تنشر أي ملف كاختبار تلقائيًا.
- أُضيف إرفاق الصور وملفات PDF إلى المدرّس الذكي، مع تحقق نوع الملف وحجمه على الخادم، وعدم حفظ بايتات المرفق في سجل المحادثة. لم يُنفذ بعد استيراد ملفات المحتوى إلى بنك الأسئلة.
- توجد مساحة رسم للطالب وسبورة مدرس تعرض خطوات الحل ورسومًا توضيحية مولدة. لم تكتمل بعد سبورة متجهية تفاعلية كاملة تدعم التكبير والتحريك وتحرير الأشكال والمعادلات والكتابة المتزامنة على جميع الأجهزة.
- لم يُنفذ منشئ صفحات مرئي بالسحب والإفلات أو نظام الكوبونات وإدارة مزايا الباقات. المحرر الحالي يتيح HTML/CSS/JavaScript مع معاينة معزولة وسجل نسخ.
- أُضيف التحقق الإجباري من البريد في الإنتاج واستعادة كلمة المرور عبر رموز مؤقتة. يحتاج التشغيل الفعلي إلى توثيق نطاق Resend وإضافة `RESEND_API_KEY` و`EMAIL_FROM` في أسرار الاستضافة.
- لم تُنفذ اختبارات قبول Safari/iOS أو Android على أجهزة فعلية.

- نجح GitHub Actions على commit `946b2e1345e14aab61922b4082e5fa98915cdea1`: `npm ci` و`npm run build` و`npm run check` (41/41) وPlaywright Chromium (5/5) وبناء Docker. [سجل التشغيل](https://github.com/rzmh1/rzmh/actions/runs/44859697709).

## حدود الأمان

- العمل محصور في فرع التطوير.
- لا توجد تغييرات على إعدادات Northflank أو أسرار الإنتاج.
- لم تُقرأ أو تُعدل قاعدة بيانات إنتاج.
- لا توجد عمليات نشر أو دمج.
- الجداول الجديدة إضافية، ولا تحذف أو تعدل سجلات الطلاب والاشتراكات والنتائج السابقة.
