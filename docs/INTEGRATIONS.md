# ربط التخزين والدفع والمدرّس

## رفع الملفات والتخزين السحابي

1. أنشئ Bucket خاصًا في Amazon S3 أو Cloudflare R2 أو مزود S3 متوافق. لا تفعّل Public Access.
2. أنشئ صلاحيات محدودة للحاوية لرفع وقراءة وحذف الملفات وعمليات Multipart، مع HeadBucket/ListBucket، واحفظها في بيئة الاستضافة:

```dotenv
STORAGE_DRIVER=s3
S3_ENDPOINT=https://YOUR-S3-ENDPOINT
S3_REGION=auto
S3_BUCKET=YOUR-PRIVATE-BUCKET
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

استخدم المنطقة الصحيحة لحساب S3؛ `auto` مناسب لـ R2. لا تدخل المفاتيح داخل الواجهة أو ملفات dist.

3. اضبط CORS للحاوية على أصل موقعك فقط، ليس `*`. مثال القاعدة (ضعها داخل CORSRules لدى AWS أو ضمن مصفوفة القواعد لدى R2):

```json
{
  "AllowedOrigins": ["https://YOUR-DOMAIN"],
  "AllowedMethods": ["GET", "HEAD", "PUT"],
  "AllowedHeaders": ["*"],
  "ExposeHeaders": ["ETag", "Content-Length", "Content-Range"],
  "MaxAgeSeconds": 3600
}
```

4. أعد تشغيل الخادم. من الإدارة ← الفيديوهات والملفات ← اختبار التخزين.
5. اختر الملف من جهازك. حدّد الدورة والدرس والصورة المصغرة ثم ارفع. يمكن رفع الصورة أولًا مع «إتاحة الصورة للجميع» للشعارات وصور الدورات، ثم اختيارها من محرر الدورة.
6. يظهر تقدم الرفع، ثم معالجة 720p للفيديو، ثم حالة «جاهز». اختيار درس موجود يربط الفيديو الجديد به بدل السابق؛ حذف السابق يتم من المكتبة بعد التأكد من البديل.

رفع الملفات الكبيرة يتم مباشرة إلى الحاوية بأجزاء وروابط موقعة. تحويل الفيديو يحتاج مساحة قرص مؤقت تكفي المصدر والناتج؛ لا تُخزّن بايتات الملف داخل SQLite. الملف المدفوع لا يحصل على رابط تشغيل إلا بعد تحقق صلاحية الحساب، وتنتهي صلاحية رابط S3 خلال 60 ثانية عند إصداره. هذا تحكم بالوصول وروابط قصيرة الصلاحية، وليس DRM يمنع نسخ المحتوى بعد السماح بتشغيله.

إذا فشل الرفع بسبب CORS، راجع الأصل وExposeHeaders للـ ETag. أضف Lifecycle لإلغاء Multipart غير المكتمل لدى المزود لتجنب بقاء أجزاء مهجورة.

## Stripe Checkout

لم يحدد الطلب مزودًا نهائيًا، لذلك أُنجز موصل Stripe فعلي مع فصل كوده في `server/payments.mjs`. تأكد أن حسابك يدعم النشاط والعملة SAR. اختيار مزود آخر يحتاج موصلًا رسميًا له، وليس مجرد وضع مفاتيحه في حقول Stripe.

1. من الإدارة ← بوابات الدفع: اختر Stripe، وضع Test Mode، ثم أدخل Secret Key التجريبي. Public Key متاح كإعداد؛ Checkout المستضاف الحالي لا يحتاج تحميله في المتصفح.
2. من حساب Stripe أنشئ Webhook إلى:

```text
https://YOUR-DOMAIN/api/payments/webhook
```

واشترك في:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`

3. ضع Webhook Secret، واحفظ، ثم اضغط «اختبار الاتصال». يختبر مفتاح الخادم بطلب مصادق إلى Stripe ويتحقق من تطابق Test/Live. لا يعني اختبار الاتصال أن Webhook أُعدّ صحيحًا؛ اختبر رحلة Checkout أيضًا.
4. فعّل البوابة. يدخل الطالب، يختار مدة، يراجع السعر ثم ينتقل إلى صفحة Stripe الآمنة.
5. يصل Webhook بتوقيع HMAC صالح وحد زمني، ثم يتحقق الخادم أيضًا من Checkout Session عبر Stripe ويطابق رقم الطلب والمبلغ والعملة والوضع. يتم تسجيل الحدث وتفعيل الاشتراك Live في معاملة واحدة، مع منع التكرار.
6. مدفوعات Test تسجل كتجريبية ولا تمنح اشتراكًا إنتاجيًا. لتجربة وصول الطالب للمحتوى قبل Live استخدم تفعيل اشتراك إداريًا.
7. بعد اجتياز اختبارات حسابك، انتقل إلى Live وأدخل مفاتيحه وWebhook Secret الخاص به، واحفظ واختبر مجددًا.

المبالغ المثبتة في الخادم بالهللات: 1999، 3999، 5999، 9999. صفحة النجاح تعرض حالة الطلب فقط؛ لا تنشئ اشتراكًا ولا تثق بمعامل query في الرابط. صفحة الفشل/الإلغاء لا تمنح وصولًا. قد تتأخر إشارة Webhook، فتظل الحالة «بانتظار التأكيد».

في وضع «رابط خارجي»، يتحول الطالب إلى الرابط فقط، وتظل العملية غير مؤكدة. لا يوجد تفعيل آلي لهذا الوضع. بعد مراجعة الدفع الفعلي في حساب مزودك يمكن للمالك التفعيل إداريًا. لا تستخدم رابطًا ثابتًا بدل API Stripe وتتوقع تفعيلًا تلقائيًا.

بديل إدخال الأسرار من الإدارة: `STRIPE_SECRET_KEY` و`STRIPE_WEBHOOK_SECRET` في مخزن أسرار الاستضافة. لا تضعها في JavaScript أو LocalStorage.

## OpenAI Responses API

1. وفّر حساب API بمفتاح ومخصص استخدام، ثم افتح الإدارة ← المدرس الذكي.
2. ضع API Key، أو اضبط `OPENAI_API_KEY` في أسرار الاستضافة. حدّد النموذج المتاح في حسابك؛ القيمة الافتراضية `gpt-4.1-mini`، ويمكن تغييرها.
3. عدّل تعليمات المدرس، والحد اليومي (الافتراضي 7)، وMax Output Tokens. Temperature ترسل فقط مع GPT-4.1 وGPT-4o في الموصل الحالي؛ اتركها فارغة للنماذج الأخرى.
4. أسعار Input/Output اختيارية بالدولار لكل مليون توكن، لتقدير التكلفة. لا تُختلق تكلفة عندما تكون الأسعار غير مضبوطة؛ فاتورة المزود هي المرجع النهائي.
5. احفظ ثم اضغط Test Connection. ينفذ الخادم طلبًا حقيقيًا إلى `POST https://api.openai.com/v1/responses`، ويعرض النجاح بعد استجابة نصية صحيحة فقط. لا يُجرى أي اختبار حقيقي تلقائيًا في حزمة التسليم دون مفتاحك.
6. فعّل الخدمة. يصل إليها الطالب صاحب الاشتراك النشط من `/#/tutor`. يحفظ الخادم محادثته وسياق آخر 16 رسالة، ويضم محتوى الدروس وبنك الأسئلة المتاح إلى السياق التعليمي. عند موافقة الطالب من إعدادات رحلته فقط، تضاف بيانات ملفه التعليمي واختياراته وخطته ونتائج اختباراته؛ لا يرسل البريد أو بيانات الدفع. البيانات المرجعية محدودة بطول معين؛ هذا ليس فهرس بحث دلالي كاملًا لكل الملفات أو PDF.
7. لكل طالب حد يومي محسوب بتوقيت السعودية، ويُحجز الطلب قبل الاتصال لمنع تجاوز الحد بالتوازي. فشل الخدمة لا يستهلك الحصة، ويسجل كتجربة فاشلة. زر التعطيل يوقف الطلبات الجديدة من الخادم.

الأسرار محفوظة مشفرة عند إدخالها من الإدارة، ولا تعود في استجابة إعدادات API. قد ترسل أسئلة الطالب والسياق التعليمي المختار إلى OpenAI؛ سياسة الخصوصية وموافقة الاستخدام النهائية تُعتمد من المالك قبل الإطلاق.

## التخصيص المتقدم

الإدارة ← التخصيص المتقدم. لكل من HTML وCSS وJavaScript محرر مستقل بأرقام أسطر وتلوين وبحث وتراجع وإعادة.

- المعاينة تتحدث بعد الكتابة. يمكن حفظ مسودة دون تغيير الموقع.
- النشر ينشئ نسخة ثابتة ويجعلها فعالة للنطاق المختار.
- سجل النسخ يسمح بفتح نسخة أو استعادتها ونشرها كنسخة جديدة.
- الأكواد تعمل في iframe مع `sandbox="allow-scripts"` دون `allow-same-origin`، وCSP تمنع الشبكة والنماذج والإطارات الداخلية. لا تملك الأكواد جلسة الإدارة أو وصول DOM الأب أو API التطبيق.
- HTML/CSS/JS هنا تضيف مناطق مخصصة معزولة؛ لا تحقن JavaScript في التطبيق الرئيسي ولا تعيد تشكيل DOM الأصلي. هذا حد مقصود لحماية حسابات الطلاب. تغيير ألوان الهوية والعناوين والصور الأساسية متاح من محرر الهوية، والتعديلات الجذرية على قالب التطبيق تبقى في المصدر.
